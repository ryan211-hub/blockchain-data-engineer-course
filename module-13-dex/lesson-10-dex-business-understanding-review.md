## 综合案例：ABC Token 上线后的第一周

假设一家 Web3 项目发行了 `ABC Token`，并在 Ethereum 上的 Uniswap v2 建立一个 `ABC/USDC` Liquidity Pool。

我们跟随这个 Pool 上线后的几个业务事件，观察用户、项目方、LP 和交易者之间的关系。

以下均为教学假设，并非真实项目。

### 问题一：项目方通过 DEX 卖出了 Token 吗？

业务场景判断 · Token Launch

项目方首先创建一个 ABC/USDC Pool，投入：

```text
项目方提供初始流动性：

ABC Token
+
USDC
      ↓
Uniswap Liquidity Pool
```

随后 Alice 使用自己的 1,000 USDC，通过 Swap 买入 ABC。

项目方在社交媒体上宣布：

> Alice 买入了价值 1,000 USDC 的 ABC，所以项目方获得了 1,000 USDC 的销售收入。

**请判断：**

1. Alice 支付的 1,000 USDC 首先进入了哪里？她实际与谁完成交易？
2. 项目方将这笔交易直接称为自己的销售收入，准确吗？为什么？
3. 如果项目方控制着相应的 LP 份额，它与这笔交易的经济利益是什么关系？

### 问题二：为什么套利者愿意帮助两个 Pool 调整价格？

业务机制与参与者利益 · Arbitrage

上线第二天，ABC 在两个 Pool 中出现不同报价：

```text
新 Pool A:
1 ABC ≈ 1.5 USDC

成熟 Pool B:
1 ABC ≈ 2.0 USDC
```

套利交易者发现了这个差异。

**请回答：**

1. 如果套利者想利用价差获利，他应该在哪个 Pool 买入 ABC，在哪个 Pool 卖出？
2. 这种交易为什么可能使两个 Pool 的价格逐渐接近？
3. 套利者、普通交易用户和 LP 在这个过程中分别可能获得什么利益，或承担什么风险？

不需要计算具体套利利润。

### 问题三：交易量暴涨一定代表项目成功吗？

商业模式与指标解释边界 · Trading Incentives

上线第三天，项目方启动交易激励：

> 只要在 ABC/USDC Pool 进行交易，就有机会获得额外的 ABC Token 奖励。

随后，ABC Pool 的每日 Trading Volume 大幅增加。

分析人员还观察到：相当多的交易集中于少数地址，并且部分地址频繁地买入、卖出 ABC。

**请判断：**

1. 能否直接根据 Trading Volume 大幅上涨，就断定 ABC 的真实市场需求大幅增长？
2. 交易奖励为什么可能改变交易者的行为？
3. 如果你需要向投资者解释 ABC 的业务增长质量，还希望补充观察哪些业务现象？

这里不是要求证明存在 Wash Trading（刷量交易），而是要求判断指标能说明什么、不能说明什么。

### 问题四：交易成功，为什么用户仍然可能觉得遭受了损失？

交易执行风险 · MEV / Slippage

第四天，Alice 通过 DEX 买入 ABC。

交易发起前，界面显示预计能获得：

```text
Expected Output: 100 ABC
Minimum Output:   95 ABC
```

Alice 提交交易后，最终只得到：

```text
Actual Output:    96 ABC

Transaction Status: Success
```

区块里还出现两笔可疑的交易，分别发生在 Alice 的交易之前和之后。

**请回答：**

1. 为什么 Alice 只收到 96 ABC，但 Transaction 仍然成功？
2. 前后两笔可疑交易可能提示什么类型的交易风险？
3. 仅凭这些现象，能否确定 Alice 一定遭受了 Sandwich Attack（夹子攻击）？为什么？

只需理解业务现象，不要求分析 MEV Bot 的实现算法。

## 用户回答（综合检查｜问题一：Token Launch / 项目方与 LP 的经济关系）

问题一：

1. Alice 支付的 1000 USDC 首先进入了 liquidity pool，它是基于 pool 完成了交易
2. 不准确，因为它只是等价兑换
3. 项目方有着相应的 LP 份额，那么这笔交易产生的手续费，可以通过 LP 份额来计算项目方的收益

## 教师判断 / 校准（问题一）

**判定：通过。三个回答的核心判断正确，其中第 2、3 点需要补充一些业务上的区别。**

### 1. Alice 的 1,000 USDC 进入哪里？

**正确。**

Alice 的 USDC 进入 ABC/USDC Liquidity Pool，Pool 按照 AMM 机制向 Alice 支付相应数量的 ABC。

从业务视角看：

```text
Alice
  │
  ├── 支付 1,000 USDC ──→ Pool
  │
  └── 收到 ABC       ←── Pool
```

这里的交易对手是 Pool，而不是项目方的钱包地址。即使交易通过 Router 执行，也不改变 Pool-level Swap 的基本经济关系。

### 2. 项目方是否获得了 1,000 USDC 的销售收入？

**你的结论正确：不能直接这样认定。**

不过，“只是等价兑换”还不足以解释原因。

关键在于区分：

- **Swap 成交额**：Alice 使用 1,000 USDC 兑换 ABC。
- **项目方实际收入**：项目方是否取得了可支配的收入，以及通过什么业务机制取得。

Alice 支付的 USDC 成为 Pool 的资产，并没有直接转入项目方的钱包。

但项目方如果同时是 LP，就可能间接享有 Pool 中的部分经济利益。因此，也不能反过来说项目方完全没有从交易中受益。

### 3. 项目方作为 LP 如何获益？

**基本正确。**

项目方持有 LP 份额，就可以分享相应的 Pool 经济利益，其中包括交易手续费形成的收益。

对于 Uniswap v2，手续费通常累积在 Pool 中，而不是每发生一笔 Swap，就直接转账给每个 LP。

还有一个区别：

**LP Fee Income 不等于 LP Net Profit。**

项目方持有的 LP 份额对应的资产组合也会随着交易变化。计算最终收益，还需要考虑资产价格变化、持仓份额以及可能适用的协议手续费等因素。

### 本题结论

你已经正确理解了最重要的业务关系：

**Trader 与 Pool 发生交易；LP 提供资金并承担相应的经济风险；项目方即使同时是 LP，也不能直接把整个 Pool 的交易额计为自己的销售收入。**

问题一通过，无须继续补考。
